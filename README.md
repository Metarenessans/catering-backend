# 🐍 Backend API & Панель Управления «Шеф Мил Фуршет» (Django & PostgreSQL)

Этот каталог содержит исходный код серверной части (бэкенда) для проекта **«Шеф Мил Фуршет»**. Приложение предоставляет полноценный REST API, административную панель управления контентом и интегрируется с контейнеризованной базой данных PostgreSQL.

---

## 🏗️ Архитектура Бэкенда и СУБД

Бэкенд-приложение отвечает за хранение каталога товаров, обработку корзин, создание неизменяемых снимков заказов, сохранение заявок на подбор меню и управление контентом (FAQ, настройки компании).

### 🔹 Технологический стек бэкенда
*   **Среда / Каркас:** Django 5.0 (Python 3.12)
*   **API Framework:** Django REST Framework (DRF)
*   **Документация API:** Swagger / OpenAPI 3.0 (с использованием `drf-spectacular`)
*   **Аутентификация:** JWT (SimpleJWT)
*   **Django-приложения (Apps):**
    *   `catalog` — Категории, продукты (блюда), фильтрация и опции цен.
    *   `orders` — Оформление заказов с сохранением сериализованных снимков (snapshots) продуктов для защиты истории покупок от последующих изменений цен.
    *   `menu_requests` — Заявки на индивидуальный подбор меню с форматами мероприятий и списком дополнительных услуг.
    *   `faq` — Управление разделом вопросов и ответов.
    *   `company` — Синглтон-настройки компании (минимальная сумма заказа, телефоны, ссылки на соцсети).

### 🔹 Архитектура Базы Данных (Docker)
*   **СУБД:** PostgreSQL 16 (легковесный официальный образ `postgres:16-alpine`).
*   **Изоляция и порты:** База данных запущена в Docker-контейнере `catering_db_container`. Порт `5432` контейнера проброшен на порт **`5433`** хоста, но привязан **исключительно** к локальному адресу `127.0.0.1`. Прямой доступ из глобального интернета закрыт.
*   **Персистентность:** Хранилище подключено к Docker Volume `postgres_data` для персистентного хранения информации при перезапуске контейнера.

### 🔹 Развертывание и выполнение (Production)
На боевом сервере **`157.22.192.108`** бэкенд настроен следующим образом:
*   **Среда выполнения:** Python-окружение запущено внутри виртуальной папки `venv`.
*   **WSGI-сервер:** Исходный код обслуживается сервером **Gunicorn**, привязанным к `127.0.0.1:8000`.
*   **PM2:** Запуск скрипта Gunicorn контролируется диспетчером процессов **PM2** (имя процесса: `backend`, ID: `2`, режим запуска: `fork`).
*   **Путь на сервере:** `/root/catering/backend`

### 🔹 Маршрутизация в Nginx (API & Статика)
Nginx принимает трафик на портах 80/443 и перенаправляет API-запросы на Gunicorn, а статические файлы отдает напрямую с диска:
```nginx
# API Запросы
location /api/ {
    proxy_pass http://localhost:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_intercept_errors on;
}

# Панель управления Django Admin
location /admin/ {
    proxy_pass http://localhost:8000;
    proxy_set_header Host $host;
}

# Статические файлы (Nginx напрямую)
location /static/ {
    alias /var/www/catering/static/;
}

# Медиа-файлы (Nginx напрямую)
location /media/ {
    alias /var/www/catering/media/;
}
```

## 🔄 GitLab CI/CD Пайплайн Деплоя (`.gitlab-ci.yml`)

Для бэкенда настроена автоматическая система Zero-Downtime развертывания:

1.  **Сборка во временной папке:** Код клонируется в `/root/catering/backend_build`. Существующая папка `venv` копируется из живой директории, чтобы `pip install` работал инкрементально и не тратил время.
2.  **Проверка целостности:** Выполняется команда `manage.py check --deploy`. Если в конфигурации Django есть ошибки, деплой останавливается до переключения путей.
3.  **Безопасные миграции:** Скрипт запускает `manage.py migrate`. При сбое подключения к СУБД скрипт автоматически выполняет команду сброса пароля администратора в Docker-контейнере и повторяет миграцию. Если это не помогает — деплой прерывается, а живой бэкенд остается нетронутым.
4.  **Сбор статики:** Статические файлы собираются в общую папку через `manage.py collectstatic`.
5.  **Атомарный своп папок:** Рабочая папка `/root/catering/backend` мгновенно заменяется на `/root/catering/backend_build` с помощью переименования на уровне ОС за доли секунды.
6.  **PM2 Restart & Health Check:** Перезапускается процесс `backend` в PM2, после чего отправляется проверочный запрос на `/api/v1/catalog/`. Если API возвращает ошибку, пайплайн завершается со статусом "failed".

## 🚀 Инструкция по Локальному Запуску (Development)

Выполните следующие шаги для локального запуска бэкенда:

### 1. Запуск СУБД через Docker
В папке бэкенда уже находится настроенный файл `docker-compose.yml`:
```bash
docker-compose up -d
```
*Контейнер PostgreSQL запустится в фоновом режиме на порту 5433 локальной машины.*

### 2. Подготовка Python окружения
Создайте и активируйте виртуальное окружение, а затем установите зависимости:
*   **Windows (PowerShell):**
    ```powershell
    python -m venv venv
    .\venv\Scripts\Activate.ps1
    pip install -r requirements.txt
    ```
*   **Linux / macOS:**
    ```bash
    python3 -m venv venv
    source venv/bin/activate
    pip install -r requirements.txt
    ```

### 3. Конфигурация (.env)
Скопируйте конфигурацию окружения:
```bash
cp .env.example .env
```
*(По умолчанию в файле настроены параметры для подключения к PostgreSQL на порту 5433).*

### 4. Миграции и создание Администратора
Создайте таблицы в БД и добавьте пользователя для админки:
```bash
python manage.py migrate
python manage.py createsuperuser
```

### 5. Загрузка демонстрационных данных
Для быстрого старта загрузите демонстрационные категории, блюда, FAQ и настройки компании:
```bash
python manage.py load_mock_data
```

### 6. Запуск сервера разработки
```bash
python manage.py runserver
```
*   **Бэкенд доступен по адресу:** `http://127.0.0.1:8000`
*   **Админка:** `http://127.0.0.1:8000/admin/`
*   **Интерактивный Swagger API:** `http://127.0.0.1:8000/api/docs/`

## 🛠️ Администрирование на Продакшн-Сервере

Для управления процессами бэкенда и базой данных подключитесь по SSH: `ssh root@157.22.192.108`

### 🔹 Управление Django-сервисом (PM2)
*   **Проверить статус процессов:** `pm2 status`
*   **Перезапустить бэкенд вручную:** `pm2 restart backend`
*   **Логи бэкенда в реальном времени:** `pm2 logs backend`

### 🔹 Управление СУБД (Docker)
*   **Проверить статус контейнера базы данных:**
    ```bash
    docker ps -f name=catering_db_container
    ```
*   **Посмотреть логи СУБД:**
    ```bash
    docker logs catering_db_container
    ```
*   **Перезагрузить базу данных:**
    ```bash
    docker restart catering_db_container
    ```
*   **Создать резервную копию БД (дамп) на сервере:**
    ```bash
    docker exec -t catering_db_container pg_dumpall -U postgres > /root/catering_db_backup_$(date +%F).sql
    ```
